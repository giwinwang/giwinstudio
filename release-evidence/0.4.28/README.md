## 一、拖拽性能：大项目拖卡片不再顿挫

### 问题定位

先用真实路径测量，发现之前"满帧"的结论是假象：**滚轮缩放和拖拽平移走的是 CSS 快路径，期间根本不重绘**。真正每帧重绘主图层的是**拖动节点**。

在 169 节点 / 47 图的最大项目上，把视图缩到 15%（133 个节点同时可见）拖动卡片：

| 指标 | 调整前 | 调整后 |
| --- | --- | --- |
| 帧率 | 43.1 fps | **55 ~ 58.5 fps** |
| 单帧 p95 | 50 ms | **16.8 ms** |
| 超过 33 ms 的帧 | 15 个 | **2 个** |

### 原因

拖拽时主图层每帧全量重绘，941 个形状里有 **917 个开着阴影**，阴影一项就占单帧绘制成本的 55%。同一视角下 `mainLayer.draw()` 平均 19.45 ms，关掉阴影后降到 8.7 ms。

### 改法

只在**拖动 / 变换进行中**临时关闭"非拖拽对象"的阴影，松手立即恢复：

- 钩子挂在 4 处：Konva 原生拖拽、变换的起点与终点，以及代理拖拽的启动与结束
- 被拖动的节点**保留自己的阴影**，视觉焦点不闪
- 节点数少于 60 的项目完全不启用（现有客户项目 20~50 节点，零影响）
- 两道保险：20 秒兜底定时器 + 手势结束时的视口收敛恢复，拖拽事件异常中断也不会永久丢阴影
- 开关成本实测：dim 0.8 ms / restore 0.6 ms

### 仍存在的边界

单帧绘制预算在最坏视角下仍接近 33 ms 上限。阴影之外约 8.7 ms 是硬成本（文字重排 3.0 ms、图片合成、连线）。**项目规模再上一档（300+ 可见节点）会突破 33 ms**，这是下一轮的目标，不是本版解决的问题。

## 二、授权页可用性：四个全屏页都能关窗

### 问题

窗口是 `frame: false` 无边框的，最小化/关闭按钮只写在主界面顶栏里。而协议页、登录页、授权页是覆盖全屏的独立页面，**既没有关闭按钮，也没有拖拽区**——用户进到这些页面后，既关不掉，也拖不动窗口。

最严重的是协议页（`screen-eula`，z-index 300）：**全新安装的用户第一眼看到的就是它**，还没见到激活页就被困住了。

### 改法

给四个全屏页各加一条 44px 顶部工具条：右上角最小化 + 关闭按钮（46×44），整条可拖动窗口。

- 覆盖页面：`screen-eula`、`screen-splash`、`screen-auth`、`screen-license`
- 按钮复用主界面顶栏的视觉，走同一套 `window:minimize` / `window:close` IPC
- 实测按钮贴右边缘、协议卡片与授权卡片顶部均无遮挡；点击关闭后进程真实退出

## 三、版本号治理：从三处硬编码收敛到单一来源

### 问题

同一个版本号在四个地方各说各话，导致用户拿到包装完不知道自己是哪版：

| 位置 | 调整前 |
| --- | --- |
| `package.json` | `0.4.28-dev.5` |
| `installer/build-installer.ps1` | 写死 `GIWIN-Studio-0.4.27-Beta-Setup.exe` |
| `installer/Installer.cs` / `Uninstaller.cs` | 写死 `0.4.25`（程序集版本、注册表 DisplayVersion、安装界面标签、安装标记文件） |
| `README.md` | `0.4.25` |

### 改法

`package.json` 成为唯一来源：

- `build-installer.ps1` 读取 `package.json` 的 `version`，输出名与版本自动跟随
- 编译前生成 `build/AppVersion.g.cs`，安装器与卸载器的程序集版本、注册表项、界面标签全部引用它
- 新增 3 条测试守住这件事：三处 JSON 版本一致、安装器脚本不得写死安装包名、C# 源码不得写死版本号

## 四、权益文案更正

软件内「订阅与授权」页原本写着：

> 内测期间全部功能开放，无需额外订阅。

但实际上：**头像自定义**是订阅权益（beta 版锁定），**粒子魔方**仍在开发中（入口保留、点击提示"后续版本开放"）。这句文案会让内测用户把正常的产品决策误判成软件故障。

改为逐项说明：「内测期间除『粒子魔方』（仍在开发中，入口保留但暂不开放）和『头像自定义』（订阅权益）外，其余功能均已开放，无需额外订阅。」

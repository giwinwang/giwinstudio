# 极物 GIWIN 产品与交互长期记忆

这份文件用于保存已经与用户确认、不能遗忘的产品约束。后续开发先读本文件，再改动画布。

## 不可妥协的交互原则

- 所有功能、视觉、节点框架、排版、动效和性能修改都必须以不损害操作手感为前提，交互丝滑优先于新增效果、瞬时最高清晰度和代码便利性。
- 在动手前先判断改动是否可能增加点击、拖动、平移、缩放、框选、连线或菜单打开的主线程开销；若有影响风险，必须提前提醒用户，并说明可采用的低风险替代方案。
- 常见画布操作验收目标：正常帧间隔约 16–20ms、P95 不高于 20ms、不得出现连续超过 33ms 的掉帧，也不得引入用户可感知的 50ms 以上长任务。视觉特效、后台缓存、纹理加载和 DOM 重排不得与交互帧争抢主线程。
- 每次涉及画布结构或视觉层的修改完成后，必须实际运行并至少检查空闲、点击选中、节点拖动、画布平移、滚轮缩放和框选；不能只做语法检查或只报告“已修改”。
- 新增节点外壳或视觉效果必须控制绘制对象和阴影数量，优先使用独立轻量层、缓存或屏幕空间绘制；不得让不可见节点、旧版底板、装饰动画或后台任务继续参与主画布整层重绘。

## 产品目标

- 面向室内设计工作流：SU / 3ds Max 等空间机位截图 -> 一致性生图 -> 局部修改 -> 方案对比 -> 排版交付。
- 同空间多机位必须保持结构、材质、光影、软装气质一致。
- 商用方向不只住宅，还包括商业、店铺等空间。
- 后续需要视频、客户方案册、软装报价与商品链接。

## 画布交互约束

- 用户说“节点”时默认包含图片节点，以及生成、参数、工具、版式、材质、光影等全部画布节点；后续讨论、排查和修改不得把图片节点排除在“节点”之外。
- 节点就是面板，不额外出现功能重复的摘要卡。
- 参数控制已合并进生成节点，不再新建独立参数节点。
- 生成节点采用“参考图 -> 方案配方 -> 核心参数 -> 生成按钮”的紧凑结构；引擎、结构保持、补充要求移到标题栏齿轮弹窗。
- 生成面板不再显示“参考图”标题行；两张缩略图自带“结构图 / 风格参考”标签，互换按钮位于两图中间。
- 参考图缩略图高度提升到 92px；主面板不再显示高级设置行，避免挤压图文区域。
- 生成节点结构输入最多连接 4 个机位；面板按机位横向排布，每张缩略图左上角显示 1–4 序号。
- 画布上对应的结构参考图片节点也显示同样样式的序号角标；第 5 个机位会被拒绝。
- 方案/天气行取消外层底色和边框，光影摘要行从主面板移除；光影值仍由光影节点控制。
- 生成面板上半部分独立滚动；生成按钮紧随模型参数，底部状态行固定在面板底部左右角。
- 生成节点与光影节点的底部状态行统一为左右两个角：左侧实时状态，右侧固定说明；两个面板的状态行都贴近面板底部。
- 节点左右端口都可发起连接；端口统一使用竖向长条，连线精确落在长条中心。
- 连线与端口统一使用浅蓝色，不按类型区分颜色。
- 画布所有蓝色系（选中、端口、连线、按钮、拖拽高亮）统一为 `#83A0B2` / `rgb(131,160,178)`。
- DOM 参数面板不能裁切连接端口；面板 overflow 必须为 visible，端口完整露出。
- 图片节点与 DOM 参数节点的端口统一为屏幕尺寸 7×32px 的细长竖条，位置按节点可视边缘计算，缩放时保持同一屏幕尺寸和间距。
- 连接端口仍放在独立的最高层，但必须按所属节点真实 `zIndex` 做遮挡判断：端口中心落在更高层级节点范围内时隐藏，上层移开或下层节点置顶后自动恢复；拖动用的端口刷新也复用同一规则。
- 图片节点的端点必须常驻显示，不依赖悬停或选中；每个可见的 Konva 节点都有一对固定端口，与参考节点使用同一尺寸和边缘定位规则。
- 节点运行中（生成、识别、对话等）其连线显示流动虚线与移动亮点；结束后自动停止动画。
- 所有节点卡统一为浅色面板、14px 圆角、2px 边框、统一的 45px 标题区规格、12px 内容边距和底部状态区；图片节点使用同一外壳规范但保留全幅图片内容，不使用蓝色左侧色块。DOM 面板可使用轻量 CSS 阴影；Canvas 节点不得再把大范围阴影直接烘焙进图片或节点本体，选中光晕使用独立 DOM 背景层。
- 所有节点采用固定的“顶部框架 / 中部内容层 / 底部框架”结构：顶部和底部高度、边距、文字基线与分隔规则固定，只有中部业务内容允许变化。节点总尺寸不随内容增减而改变；内容增加时在既定中部安全区内优先压缩间距和重排，内容减少时重新分配纵向呼吸空间。压缩不得低于可读性下限，无法继续容纳时应使用分组、展开或分页，不得撑大外壳或出现内部侧边滚动条。
- 所有节点底部框架统一为 22px 高，底部文字或状态行固定距左右边框 12px、距底边框 10px；DOM 节点与 Canvas 节点共用同一安全区，不得再使用各自的 H-18、H-27、H-38 等独立底部坐标。
- 所有节点中部内容层共用一套疏密变量：正常档区块/行/标签/内容到底栏分别为 10/8/4/8px，舒展档 12/10/4/10px，紧凑档 6/4/3/4px，高密档 4/3/2/2px。内容减少时优先进入舒展档分配剩余空间，内容增加时依次压缩；禁止各节点单独写 gap、margin 或 padding 来形成另一套间距。
- 旧工具节点即使存档仍记录 360px，也必须按统一 408px 外壳重建；材质节点填写 7 项以上时主动使用紧凑密度，不能等到内容碰到或遮住底栏才压缩。
- 中部内容必须按语义分组后再分配空间：同一功能组内部使用固定行距，仅在组与组之间分配剩余空间。光影节点固定分为“预设 / 参数 / 补充要求”三组，材质节点固定分为“表格内容 / 底栏”两组；输入框和表格行不得单独吸收剩余高度。
- 材质表格的数据行必须均分可用纵向空间：剩余高度分散到各数据行之间，不能全部堆积在最后一行与底栏之间；最后一行到固定底栏仍需保留统一安全间距。
- 360° 全景节点无来源图片时，中部显示纯色空状态和连接说明，不绘制占位纹理；“回到正面 / 修复全景”等操作必须禁用。工具栏与固定底栏使用统一内容安全区和间距。
- 标记节点按统一三段框架排布：机位标签、226px 高预览图、绘图按钮行、共用/本机位设置依次排列，底部状态固定在统一安全区；不得再用小预览图在底栏上方留下大块空白。
- 画布必须统一管理交互输入状态：窗口 blur、页面进入后台、鼠标在窗口外松开及隐藏/失效输入框残留焦点时，一次性清除空格、平移、框选、节点拖动、连线、切割、外部拖放和中键状态。只有可见且有效的输入框才能拦截画布快捷键；按钮、下拉框等控件获得焦点时，空格不得误触发画布平移。
- 交互丝滑优先于瞬时全清晰：显示分辨率按 32/256/512/768/1024 分级，常规近景使用 768，选中或近景必要时升级 1024；缩放手势期间禁止替换纹理、启动同步位图缓存或新的 LOD 解码。视口内已加载的 512/768/1024 纹理在缩小时直接缩放复用，只有低于 55% 才允许降档；手势结束并静置后再串行升级可见图片。Konva 节点级位图缓存会同步光栅化整张卡片，禁止在主线程启用；大项目存在画布活动时暂停后台项目预读。
- 所有功能节点与图片节点统一为 408px 基础高度，宽度由内容或图片比例决定；图片保持原始比例缩放到统一高度。
- 连接规则集中维护在 `CONNECTION_RULES`，目标节点按规则自动选择匹配输入端口。
- 不兼容连接必须被拦截并说明原因。
- 连线支持点选、Delete 断开、撤销恢复、方向箭头。
- 按住 Alt 并右键拖动可切断裂缝经过的连线，拖动路径必须显示浅蓝切割虚线；一次滑动切断的连线合并为一条撤销记录。
- 鼠标悬停到连线上时，断线按钮的中心必须落在曲线最近点上，并使用统一的 `#83A0B2` 浅蓝描边、面板底色和白色叉号；点击只断开当前连线并支持撤销，鼠标移开短暂延迟后自动隐藏。
- 拖动节点和拖动连线必须保持流畅，高频拖动只做轻量刷新。
- 导入图片只显示图片，不自动生成虚线圈组或“对比组”标签。
- 画布图片可以直接拖入参数面板的结构图、风格参考、材质参考框。
- 删除参考连线后，面板缩略图必须立即清空；撤销后恢复。
- 生成点击后立即创建带连线的占位卡；成功后原位替换，失败则变为错误卡。
- 占位卡尺寸必须按目标比例预估（例如 16:9 约 640×360），不能统一用小卡占位；批量生成必须逐张注册占位卡后再找下一处空位。
- 自动整理采用依赖分层：参考/材质/光影在左，生成居中，结果与后续动作向右；同一层并行分支按近方形网格展开，互不相连的工作流作为独立区块打包。
- 自动整理必须使用节点真实世界尺寸，禁止用屏幕缩放后的尺寸；整理后不得出现内容重叠。
- `fitView` 只按非便签节点取景，并在移动舞台后同步 DOM 参数面板与端口位置。
- 风格参考不是配色提示词：结构图作为图1、风格图作为图2 分别传给模型；单图通道才使用左右拼接的兜底参考图。
- 生成节点提供“⇄ 交换”按钮，占用两张参考图之间的独立网格列，按图片区域水平、垂直居中，不随左右栏宽度变化而偏移；底部状态提示右对齐。
- 光影节点是生成节点的上游输入，输出端口类型为 `light`；面板包含预设、强度、色温、阴影柔度、光源方向和补充要求。
- 光影面板不再显示“光影预设 / 点击套用”标题行；天气与光源方向使用同一行，文字标签和下拉框并排。
- 配方、天气、光影必须联动：切换方案配方会同步光影节点的主光影，切换天气会同步色温/强度/柔度；光影节点修改后生成参数立即更新。
- 连接光影节点后，生成面板的「方案」与「天气」各自在下方显示「以光影参数为准」注释；方案显示「跟随光影 · 当前光影预设」，天气显示光影节点的天气，两个下拉均锁定。
- 未连接光影节点时，方案与天气恢复预设可选，注释显示「预设可选」；重新连接后立即回到光影接管状态。
- 多机位出图时，占位卡总数 = 结构机位数 × 每机位数量；生成前一次性按两列网格整块预留空位，再按机位顺序逐张生成，后续机位显示排队状态。
- 同一生成节点的风格参考、空间材质与光影参数对所有机位共享；每个机位只替换自己的结构图，结果标签带机位序号。
- 结果连线在对应图片生成成功后立即恢复静态；生成节点继续处理其它机位时，已完成的结果线不再显示流光。
- 生成中的临时占位连线与普通连线使用同一套蓝色 `#83A0B2` 和流光样式，不再使用黑色虚线。
- 生成主面板的模型列上方提供「模型商」小下拉，可在阿波罗 / 火山 / RH / 自定义之间切换；切换后自动换成该厂商默认模型，并校正清晰度与比例到可用档位。
- 模型下拉按大众友好名去重，同一个模型不再因为真实 ID 不同而重复出现。
- 参考图传给模型前压到长边 1K=1536 / 2K=2048 / 4K=3072 的 JPEG（保留白色底，避免透明 PNG 变黑），并按节点与文件缓存；同一项目重复生成时参考准备约 20ms，不再重复解码 4K 原图。
- 多机位默认 4 张并发生成，高级设置可改为 1 / 2 / 4；遇到 429 或限流会自动等待后重试一次。图片落盘使用串行队列，避免多张同时保存造成卡顿。
- 生成状态点击后立即显示「正在准备 N 张参考图」，随后显示已生成数量、进行中数量、失败数量和平均每张耗时。
- 有风格参考时，结构锁定提示词以「图1」为唯一结构与相机角度基准；结构保持 ≥85 即使用绝对锁定条款，图2 与材质拼图只提供表面信息，不得影响图1构图。
- 高清放大与画室使用同一条 RunningHub AI App：App ID `1985986284411858946`，上传 `/openapi/v2/media/upload/binary`，提交 `/openapi/v2/run/ai-app/1985986284411858946`（节点 `15` 图片、节点 `106` 分辨率），轮询 `/openapi/v2/query`。
- 新建高清放大功能只保留 RunningHub 线上通道；顶部灵动岛和图片端口连线菜单的“高清放大”必须打开同一个 RunningHub 面板。不得再提供新建 `upscale-local` 本地重采样入口，也不得在线上失败时静默回退本地。旧项目已有的本地放大节点仅做兼容加载，不再作为新功能入口。
- 高清放大档位 1K/2K/4K 对应节点 106 的 1024/2048/4096；实测 2K 输入 1376×768，输出 3668×2048，RunningHub 返回放大图与锐化版两张，均写回画布。
- 节点 106 的语义是目标短边像素，不是固定倍数；UI 显示为 1×/2×/4×，并同时标注短边 1024/2048/4096。对 1376×768 输入，2× 档实际约 2.67×；若需要严格按原图短边×2/×4，需改为动态计算目标短边。
- 灵动岛「HD 放大」和工作台「RunningHub 高清放大」共用同一个面板：选 1K/2K/4K，支持一张或多张选中图片，结果自动连线；RunningHub Key 缺失或没有 AI App 权限时会给出明确提示。
- UW 另接了 Topaz Labs 的 Topaz Upscale Image / Standard V2；画室的本地 ComfyUI（127.0.0.1:8188）使用的是 BizyAir_ImageUpscaleWithModel + `4x_NMKD-Siax_200k.pth`，不是 Topaz。两条链路不要混用。
- 对比节点纳入图节点端口系统：显示左侧输入连接点，因无输出自动隐藏右侧端口；对比连线与新图连线统一为 `#83A0B2` 底色 + `#DCEBF3` 流光虚线 + 白色移动光点。
- 高清放大结果图片支持双击打开灯箱查看原图；图片结果即使带 `gwToolKind` 也不再误走工作台工具入口。
- 灵动岛直接提供高清放大图标（⤢），不必再展开“更多”菜单。
- 自动整理把图连线和旧版结果/对比连线都视为同一组关系：连通分量成组，按上游→下游分层，子节点尽量对齐父节点垂直位置，互不相连的组再分块打包。
- 自动整理的并行分支按近方形网格排列：9 张为 3×3、4 张为 2×2、2 张并排；父节点纵向对齐整个子节点网格的中心。
- 对比节点点击、拖动、缩放都不再触发流光；双击对比节点打开全屏对比，支持滚轮缩放、Alt/中键拖拽平移、滑杆擦看和 100% 复位。
- 账号头像移到画布左下角，头像菜单从该位置向上展开；顶栏不再占用头像位置。
- 头像菜单不再提供“导入图片”入口；顶部依次为“导出画布 / 快捷键 / 版本历史”，导出画布使用向上导出图标；“更换头像”和“设置”并排放在菜单最底部同一行。
- 主窗口不再保留独立系统标题栏内容行：使用无边框窗口，把 logo、软件名称、“项目”按钮、当前项目名和最小化/最大化还原/关闭控件合并到同一条 44px 顶栏。窗口控件必须直接继承深色/浅色主题，不能使用会形成异色矩形的 `titleBarOverlay`。
- Apollo 模型列表新增 `seedream-v5-pro`（显示名 Seedream 5.0 Pro），别名兼容 Seedream 5 Pro / 豆包 Seedream 5.0 Pro。
- 性能基线：画室/UW 的画布是 DOM 世界层 + CSS `transform` 平移缩放，只物化视口附近节点；连线走 SVG；输出图使用 `content-visibility:auto`；节点按 id 增量刷新；图片按缩放切换分辨率。Konva 全量重绘是卡顿主因。
- 我们采用同类策略的低风险版本：所有项目启用显示分辨率 LOD（约 256/512/768，选中图 1024、放大 ≥1.2 才用原图），图片节点显示纹理最大 1600；未选中图片关闭 canvas 阴影；场景裁剪阈值降到 8、视野外 500px 才裁剪；端口不再每帧重建，缩放时延迟 60ms 刷新；端口阴影关闭。
- 实测 18 张图片、22 节点：适应视图（14%）帧间隔从约 39ms / 最大 1019ms 降到 16.67ms；200% 缩放空闲 16.67ms；100% 约 19ms（偶发一次 LOD 解码停顿）。
- DOM 参数面板改为放进 `#gw-panels-world` 世界容器，只写节点世界坐标；平移缩放由容器统一 `transform`，不再逐帧重排面板。
- 平移采用 CSS fast-pan：拖动期间只对画布容器和面板容器做 `translate3d`，不改 Konva stage、不重绘图片；松手时一次性提交 stage 位置并重绘网格。实测平移帧间隔约 16.8ms（60fps），从约 196ms 降下来。
- 对比节点内部两张图也改用 1024 显示缩略图，原图只在双击全屏对比时读取。
- 光影面板的“补充要求”输入框拉伸填满底部剩余空间，底部状态行保持贴底。
- 光影“补充要求”输入框改为标签在上、输入框整行铺满，不再只占右半列。
- 结构图/风格图缩略图使用 512px 高质量预览；材质参考缩略图使用 256px 高质量预览。
- 所有 DOM 节点标题统一为 13px、45px 头高、12px 横向内边距；内容区横向内边距统一为 12px。
- 光影输入框、生成按钮与底部状态行之间统一留约 8px 呼吸间距，和材质节点底部留白一致。
- 生成面板上半区使用 `space-between` 自动分配剩余高度，参考图、方案/天气、模型参数之间保持均等间距，不再在按钮上方堆积空白。
- 节点字体层级由 `.gw-node-panel` CSS 变量统一：标题 13px、副标题/标签 10px、输入值 10.5px、说明 9.5px、微文字 8.5px；以后新增节点直接继承。
- 多选节点后从其中一个节点拖出连接，会批量连接所有兼容节点，并跳过没有上下游关系的节点。
- 端口拖线必须在 `mouseenter/pointerenter` 时保存拖线前的多选快照，`pointerdown/mousedown` 只能基于该快照启动批量连接；三张图片框选后从任意一张右侧端点拖到生成节点，必须一次尝试建立三条结构连线，不能只连接拖动起点。
- 多选批量拖线过程中必须为除起点外的每个已选节点绘制一条浅蓝虚线预览，并在指针/目标旁显示待连接数量；悬停目标时按兼容性和剩余端口容量更新有效数量，释放后仍落成多条独立连线。
- 连线可以框选；框选方向标准必须同时作用于节点和连线：左向右完整包含整条曲线、右向左碰到曲线即可选中。框到连线和节点时，第一次 Delete 只断开连线，保留节点。
- 空间材质包含地面、墙面、柜体、吊顶、房门、玻璃、沙发、窗帘、灯具；不包含地毯。每个材质独立保存名称、颜色和参考图。
- 材质面板采用横向行布局：材质名、名称输入、色调、参考图缩略图在同一行，9 行全部在 360 高度内可见。
- 材质行使用 46px 类别、76px 名称、34px 色调、剩余宽度给参考图；名称约显示 6 个汉字，参考图列尽量加宽并支持悬停放大预览。
- 材质面板标题栏的 `▦` 按钮可查看最终传给模型的材质参考拼图，拼图标签带序号，与提示词顺序一致。
- 每个已有参考图的材质行右侧有 `×` 清除按钮；只清除当前行参考图，保留名称和色调，并支持撤销。
- 生成时把各材质参考图按固定顺序拼成一张材质参考图，并在提示词中写明材质与参考图顺序。
- 节点卡片不能遮挡左侧工具条。
- 项目打开后必须立即隐藏 `#canvas-noproject`，并在画布加载完成与有节点巡检时再次强制隐藏；不能因为异步 `updateStatus()` 的旧状态把“还没有打开项目”提示重新显示在有内容的画布上。

## 模型与接口

- 商用字体统一为随软件打包的 `GIWIN Sans`（Noto Sans SC 400/500/700）与 `GIWIN Serif`（Source Han Serif SC Heavy）。界面、画布正文、节点、内部方案排版和当前导出链路只允许使用这两个字体族，不得回退到苹方、微软雅黑、宋体或系统 serif；字体许可证保存在 `fonts/OFL.txt`。
- 模型列表拉取功能保持关闭：设置页连接测试不得请求 `/models`，不得写入或读取 `gw_models_*`，旧缓存启动时清除。生成、局部重绘、视觉识别和节点模型菜单只使用内置 `MODEL_REGISTRY` / `BUILTIN_MODELS` 与用户当前手选模型；OpenAI、DeepSeek、阿波罗可用最小对话请求验证接口和密钥，火山/自定义仅检查 Base URL 可达性。
- 设置 → 引擎的提供商下拉按使用优先级排序：当前引擎第一；当前项目节点或配方实际使用的引擎随后；已配置 API Key 的引擎再次；其余保持登记顺序。切换或保存引擎时记住最近选择。
- 设置中的模型特性表必须覆盖全部 `MODEL_REGISTRY`：每个模型都要有用途说明、尺寸/比例或识图/对话规格、实际存在的本地 Logo。表格采用两列排版，左列模型与厂商，右列规格和定位；新模型缺任一字段时自动化测试必须失败。
- 前端显示大众熟悉的模型名，底层映射厂商真实模型 ID。
- 阿波罗中转站：
  - `NanoBanana Pro` -> `nano-banana-pro`
  - `NanoBanana 2` -> `nano-banana-2`
  - 2K / 4K 对应厂商的 `-2k` / `-4k` 模型档位。
- 阿波罗 Base URL 可填写 `https://api.apilio.ai`，客户端优先请求 `/v1`。
- 参考图生成优先走 `images/edits`；不要先走只返回文字的多模态对话。
- 多参考图优先走 `images/edits` 的多个 `image[]`；失败后走 chat 多图，再退回单张拼接参考图。
- 材质参考图当前合成一张带顺序标签的拼图，作为额外材质参考传入；提示词必须按同一顺序说明材质归属。
- 材质色调不是蒙版，且色调数据必须依附于该行参考图。没有参考图时不显示、不可编辑、也不向提示词或生成请求提交色调；旧的无参考图色值在保存时清除。上传或更换参考图时自动读取图片主色，删除参考图时同步清空色调。色调联动必须在客户端按目标色生成调色后的材质参考图，保留原图文件和纹理明暗，并让调色图实际进入多图编辑请求；生成不得只带色值提示词而遗漏材质图片。调色弹窗需提供足够大的实时预览，并分别提供目标色、总强度、色相、饱和度和明度；移动任一色彩参数都应自动启用联动并立即刷新预览，点击完成才统一提交。每行保留跟随色调开关和恢复原色，调色结果可缓存但不可覆盖原图。
- 画布图片或生成结果必须可以直接拖到空间材质面板的具体参考框，添加为对应材质参考图，并与风格参考拖放保持同一套直接操作习惯。拖放成功后来源图片节点回到原位；自定义拖拽接管时，松手阶段也必须执行 DOM 面板和材质槽命中，不能只依赖 Konva 原生 dragend。
- 空间材质列显示为“类别”，使用可输入的下拉候选；视觉识别结果先匹配内置材质类别库，匹配不到时保留识别原文，用户仍可选择预设或输入自定义类别。材质提示词必须逐类别锁定作用范围，明确未填写或未上传参考图的吊顶、房门、玻璃、家具等保持图1原材质，禁止墙面等已上传材质扩散到其他表面。
- 空间材质固定包含地面、地毯、墙面、踢脚线、柜体、吊顶、房门、玻璃、沙发、靠枕、窗帘、灯具；新增项必须同步材质类别库、视觉识别键、提示词范围、拖放落点和持久化。12 项时材质面板进入紧凑行高，不能挤压参考框、调色状态或底部提示。
- 参考图不是越多越准：同一次生成建议只放 3–6 个关键材质，过多会稀释模型注意力；需要精确到每个表面时，应拆成少量独立参考图或分次局部修改。
- 从画布端口拖到 DOM 参数面板时，释放点按面板矩形命中；stage 收不到 mouseup 时由全局监听兜底。
- 风格约束提示词必须明确“图1结构与机位、图2材质与光色”，不得只写“参考这张图”。
- 新增模型时必须同时维护：显示名、真实 ID、厂商、尺寸、比例、能力、Logo。

## 已实现能力

- 生成节点统一提供“空间渲染 / 视觉平面”双模式，模式保存在节点参数中并可恢复；视觉平面只生成商业视觉底图，正式标题、正文、Logo、价格和二维码留给版式节点编辑。视觉风格与文字留白位于主面板，构图、主色和补充视觉要求收纳在标题栏齿轮设置，保证两种模式使用同一固定外壳。视觉平面使用独立风格集：杂志编辑、极简留白、高级精品、品牌广告、艺术海报、产品聚焦；与空间渲染的室内风格分开保存，切换模式时各自记住上次选择。
- “方案排版”节点统一更名为“版式输出”，从上游生成结果或图片继承设计模式；版式编辑器支持 16:9、1:1 与 A4 三种页面，视觉平面模式默认使用 1:1 方版，空间渲染保持原有 16:9 方案逻辑。旧项目未写模式的节点默认保持空间渲染，不改变既有工作流。
- 多项目采用单窗口、单层 44px 顶栏标签，不增加第二行；当前项目标签使用 `#83A0B2` 底部指示和轻微底色，支持多选打开、横向滚动、拖动排序、双击重命名、未保存圆点、关闭与 `Ctrl+Tab` 切换。
- 项目标签按账号持久化；切换前必须完整保存当前画布，切换后恢复目标项目的节点、连线、图片与视口。完整重启后恢复标签顺序和最后活动项目，无标签时回到项目首页。
- 同一时间只挂载当前项目画布；生成任务运行中禁止切换，保存失败时取消切换或关闭。项目状态使用最近 6 个项目的内存快照并在空闲时预读未激活标签；图片解码缓存按项目保留最近 3 份。切换仍必须先落盘，不得用内存缓存绕过保存。
- 多项目切换只保存真实变化，禁止每次切换强制写入完整画布；画布主进程缓存必须校验基础存档与增量日志的文件指纹后再复用。工具/对比节点画布预览直接复用源图 1024px 缩略图，不在切换时重新烘焙 2048px data URL。
- Canvas 节点不使用整图大范围阴影；选中背光由独立 DOM 光晕层承担。后台缩略图加载必须分批让出主线程，并合并图层重绘。
- 节点不再使用 `Konva.cache()` 做可见节点位图缓存；该操作会在主线程同步光栅化整张卡片，复杂项目实测单节点可停顿数百毫秒。画布平移和缩放依靠视口裁剪与 CSS 预览，禁止每个滚轮事件都全量重绘 Konva 图层。
- 画布平移、缩放和手势期间暂停粒子魔方的装饰动画，手势停止后自动恢复；后台图片 LOD 同样在画布手势期间暂停，避免装饰动画和缩略图解码抢主线程。
- 图片剪贴板允许跨项目使用：同项目粘贴复用原文件，跨项目粘贴时把真实图片复制到目标项目 `Content`，不能只在目标目录查找同名文件。

- Konva 无限画布、项目保存与恢复、原子存档、版本历史。
- 生成链、空间参考、材质基准、局部重绘、标记、全景、反推提示词、对话、高清放大。
- 粒子魔方的附件不能只作为文件名列表存在：请求视觉模型时必须按附件显示顺序附带真实图片，并在提示中绑定编号。图片准备使用后台低并发压缩，不能阻塞画布点击、拖动、缩放和框选。
- 局部重绘按模型能力分流：GPT Image 1/2 走 `images/edits + mask` 原生遮罩；NanoBanana、Gemini、Seedream 等走原图 + 红色半透明区域参考图，生成后必须按蒙版和羽化参数回贴原图；RunningHub 等未验证通道暂不开放局部重绘。编辑器需显示“原生遮罩 / 参考图编辑 · 自动回贴”状态。
- Electron 画布内不能调用 `window.prompt()`；节点内局部重绘和对话必须使用画布自己的输入弹窗，并自动选择当前平台中第一个支持局部重绘的模型。
- 局部重绘的模型选择统一使用自定义上拉菜单，避免底部原生下拉框被窗口裁切；画布内嵌局部重绘节点顶部也必须提供模型入口，选择结果随节点保存，生成时优先使用节点所选模型。
- 节点内“生成重绘”必须先建立带连线的占位卡，成功后原位替换为结果节点并保留连线；同一局部重绘编辑器只能存在一个实例，双击事件要走统一的防重复入口，不能再由节点、舞台和原生监听各开一次。
- 双击局部重绘节点打开的大窗口必须把来源工具节点 id 传给生成流程（`pendingFromNodeId`），生成时同样先显示占位卡和连线，完成后在原位替换结果，不能只保存一张无血缘的结果图。
- 占位卡转失败卡时必须销毁/隐藏直接属于占位卡的状态文字，只保留错误卡自己的标题、详情和提示，不能再出现“重绘中 · 已等待”和错误正文重叠；错误文案要先识别网络、5xx、401/403、超时和 404，再判断“是否接受参考图”，避免把上游 503 或断网误报成模型能力问题。
- 图像分层不能再用本地主色 K-means 冒充物体分层。参考画室做法，调用 Seedream 5.0 Pro 图层分解模型 `doubao-seedream-5-0-pro-layer-1k/2k`，请求 `/images/generations`，传 `image[]`、`size`、`layer_decomposition:true`、`watermark:false`、`response_format:url`；返回数组第一张是背景，其余是透明元素层。用户没有乔楚画室 API，因此设置中不出现单独平台，只在已配置的阿波罗/火山平台上尝试该模型。
- 软装清单可连接最多 8 张效果图一起识图；必须使用设置中的 OpenAI / DeepSeek 视觉模型，不得拿生图模型冒充视觉识别。多图结果按名称和类别合并，重复项取最大可见数量并补齐品牌、价格、链接，不能把同一家具按不同视角重复累加。
- 软装清单内必须提供视觉模型下拉：OpenAI 可选 GPT-5 Vision / GPT-4.1 Vision / GPT-4o Vision，DeepSeek 使用 Flash 视觉模型；模型选择随清单保存。模型输出截断时先自动提升到 4096 token 并精简提示词重试，GPT-5 / o 系列使用 `max_completion_tokens`，其他模型使用 `max_tokens`。
- 视觉识图只能得到软装名称、类别、数量和画面中可见品牌，不能凭空得到真实售价或商品链接。软装节点需显示最多 9 项并注明剩余数量；价格与链接通过用户粘贴商品链接后读取商品页标题、品牌、价格（JSON-LD / OpenGraph）补齐，读取失败时保留手工填写。
- 淘宝搜同款采用 95% 自动化：视觉提取时为每件软装返回 `image` 源图序号和归一化 `box`，软装行提供「搜」按钮，自动裁图并打开独立持久化淘宝窗口，通过隐藏的 `#image-search-custom-file-input` 注入裁图；用户在淘宝登录/验证并点中商品后，主进程监听商品详情页 URL，自动回填链接、品牌和公开价格并关闭搜索窗口。关闭窗口或未选择商品时保留原数据并提示。
- 淘宝登录会话固定使用 Electron 持久化分区 `persist:giwin-taobao-search`。搜索窗口关闭时主动刷新 Cookie；软件退出时先等待 Cookie 写盘完成，再完成正常退出。用户在软件内的淘宝窗口登录一次后，正常关闭并重新打开软件不需要重复登录；淘宝侧主动使会话过期或触发安全验证时，仍需重新登录或验证。该登录状态只保存在本机软件用户数据中。
- 淘宝商品结果如果在新窗口打开，必须先拦截该链接并在受控窗口内导航到商品详情页，再读取详情页标题、品牌和价格；不能拿搜索页 HTML 当商品详情。商品价格优先读 JSON-LD / OpenGraph，再读 `.tm-price`、主价格类名等渲染后 DOM，品牌优先读商品元数据，再读品牌/店铺节点。
- 淘宝选中商品后必须同时保存商品主图到项目 `Content` 目录，CSV 增加商品图列；主图下载失败时保留商品图远程地址作为预览兜底，不能只回填链接和价格。
- 软装清单行采用卡片式布局：左侧商品图 84×68px，右侧名称/类别/品牌一行、数量/单价/商品链接一行，操作按钮独立放右侧；不再用九列单行挤压商品图。

- 网页版的每个空间分组会读取对应效果图页文案，显示为该组空间说明；PDF 每张效果图页直接绘制该页标题和正文。

## 画布性能基线（2026-10-20 实测）

- 启动异常不能再永久关闭 GPU：只有连续 3 次非正常退出或显式 `--safe-mode` 才启用软件渲染；正常退出后自动恢复。此前一次强制关闭会让之后每次启动都禁用硬件加速，22 节点项目的主画布单帧绘制会从约 3ms 恶化到 100ms 以上。
- Canvas 图片节点不直接绘制黑色投影；选中态使用独立 DOM 蓝色光晕加蓝描边，避免选中时重栅格化图片。DOM 参数面板继续使用 CSS 轻阴影。
- 视口裁剪阈值保持独立；场景运行时不得在小项目加载、变更或缩放后重新开启 Canvas 节点的大范围阴影。
- 画布显示不再加载 4K 原图：选中图按缩放使用 1024 / 1600，未选中图按 256 / 512 / 768 / 1024 分档；4K 原图只供灯箱、全屏对比和导出。
- 节点拖动在 `mousedown` 阶段接管，立即取消 Konva 原生拖拽，跨过 4px 阈值后只移动 `dragLayer` 上缓存的副本；拖动期间不更新 Transformer、不重绘主画布。实测 30 帧平均 16.67ms、最大 16.9ms，松手后 900ms 内无长任务。
- 多选拖动同样走代理：最多 16 个节点复制到拖动层一起移动，松手后一次提交全部坐标和一条撤销记录。
- 滚轮缩放按 rAF 合并，缩放中只做一次 `mainLayer.drawScene()`；端口、LOD、场景裁剪和命中层延迟 160ms 统一收尾。实测单次主画布绘制约 3ms。
- 平移继续使用 CSS fast-pan，拖动期间不重绘 Konva；实测平均 16.67ms、最大 16.9ms，整个平移过程主画布只提交 3 次绘制。
- 连接端口迁到独立 `portLayer`，端口刷新只重绘端口层，不再对每个端口 `moveToTop()` 触发主画布重绘。
- 运行中连线流光迁到独立 `flowLayer`，虚线、光点和脉冲只重绘流光层；实测 1.3 秒流光期间主画布只绘制 2 次，此前约 78 次。
- 节点拖动、缩放不再激活 60 秒流光；所有 `activateNodeFlow(..., 60000)` 已改为 1.2 秒，拖动期间暂停流光。
- `ensureStageSize()` 在尺寸未变化时直接返回，不再每次鼠标按下都重绘所有图层和网格。
- 2026-10-23 已完成：生成/材质/光影等 DOM 面板的旧 Konva 底板彻底设为不可见并退出绘制；场景裁剪逻辑只保留其逻辑可见性，不再将底板重新显示。选择样式仅更新原选中和新选中节点。Canvas 节点不直接绘制大范围阴影，选中背光改为独立 DOM 层。节点位图缓存已停用。连线悬停复用快速节点几何和 rAF 合并，禁止每次鼠标移动递归调用整组 `getClientRect()`。
- 性能诊断浮层不得占用 `F3`；用户已有其他 F3 快捷键。内部诊断统一使用 `Ctrl+Alt+Shift+D`，其他功能不得拦截该按键组合之外的无修饰 F3 事件。
- `Ctrl+A` 全选必须覆盖画布上的全部可选节点类型，包括图片、生成、参数、工具、对比、便签、光影、材质、排版、软装、合并组和失败占位；新增节点类型时必须同步加入全选白名单。

## 工具条与头像补充约定

- 左侧悬浮工具条只保留：资源与历史、导入图片、工作台、自动整理、版本历史、适应视图；生成、空间材质、光影、便签、对比不再以悬浮按钮出现，统一走右键菜单/节点/灵动岛入口。
- 原“工作台 / 工具库”右侧面板不再显示标记、局部重绘、全景、反推、对话、分层、放大等图像工具入口；这些操作统一从图片顶部灵动岛和右键菜单进入。该侧栏改为“工作流与资产”，无需选中图片即可打开。
- 资产库统一为一个左侧抽屉入口（`Ctrl+K`），不再保留独立的“资源与历史”和右侧工作流入口。首版顶层分项为“项目资源 / 通用资产 / 工作流”：项目资源包含画布图片和生成历史；通用资产保存参数/风格配方；工作流保存节点图。右侧重复的工作流按钮已移除。
- 通用资产和工作流共用资产列表、搜索、保存、导入、导出；工作流卡片可拖入画布展开，通用资产调用后应用模型、风格、尺寸和提示词。
- “保存”行为必须按当前分项明确区分：通用资产页始终保存当前生成配方，不要求选中节点；工作流页必须选中节点，未选中时提示先选择。按钮文案分别为“保存当前配方”和“保存当前工作流”，不能再用一个模糊的“保存当前内容”由选区状态猜测。
- 资产卡片预览必须与保存对象一一对应：图片素材使用保存的那张图片；参数配方保存选中节点时使用该节点面板的真实截图，无选中节点时才显示参数信息占位卡；工作流使用整个选中节点组截图。禁止从项目里随机寻找“最近生成图”充当封面。点击缩略图在原卡片内下滑展开大图，再点收起。
- 工作流预览优先保存“整个选中节点组”的真实画布截图，而不是只画节点类型示意图：保存时临时取消选择态、隐藏选择光晕/Transformer/端口/工具栏/灵动岛/资产抽屉和网格背景，自动缩放取景到全部选中节点，调用 `capture:pageRegion` 截图后恢复原视图与选区。截图必须能看到结构图、参数面板、材质面板和连线；只有截图失败时才退回结构示意图。
- 通用资产和工作流都必须支持直接拖到画布：工作流拖入后展开节点与连线；通用资产使用 `application/x-gwiasset` 拖放类型，释放到画布后应用模型、风格、尺寸和提示词并关闭资产库。
- 资产库打开时存在全屏 `drawer-scrim`，HTML5 拖放会落在遮罩层而不是画布，不能继续用 `dragstart/drop` 作为唯一拖拽通道。资产卡片必须使用自定义 Pointer Events：移动超过 6px 显示拖拽浮层，pointerup 时按坐标判断是否落在画布内，再实例化工作流、图片素材或参数配方。
- 通用资产的“调用”不能只修改右侧面板而没有任何画布反馈：选中生成节点时应用到该节点；选中一至四张图片时创建生成节点并连接这些图片；没有选中对象时在视口中央创建预配置生成节点。拖拽通用资产时强制在鼠标落点创建节点。
- 通用资产必须区分“图片素材”和“参数配方”：选中图片后使用“保存选中图片”，原图复制到用户数据 `asset-library/images`，资产记录 `kind: images` 和文件清单；调用或拖入时通过 `asset:readImage` 读回原图并在画布创建图片节点，绝不能误创建文生图节点。“保存当前配方”只保存模型、风格、尺寸与提示词，不保存图片。
- 点击图片素材时在当前视口中央放置图片节点；拖拽图片素材时在该鼠标落点创建图片节点。多选图片会作为一个图片素材组保存，并在调用时按画布网格排列。
- 工作流保存不得调用 `window.prompt()`（Electron 不支持）；统一使用软件内命名面板，字段包含名称、分类、可选说明，并显示将保存的节点数和内部连线数。
- `Shift+G` 是建立工作流的快捷键：有选中节点时打开同一保存面板；没有选中节点时提示先选择。多选普通节点保存选中子图；单个合并卡片保存其内部完整模板，而不是只保存折叠卡。合并卡片右键菜单提供“展开合并节点 / 保存为工作流… / 删除”。
- 画布右键菜单统一使用线性 SVG 图标、固定 18px 图标列、左对齐标签和右对齐快捷键；光影参数节点仍保留在右键菜单中创建。
- 头像直径与工具条厚度一致（当前 52px），始终位于工具条下方 12px 并水平居中，跟随工具条换边、抽屉打开、窗口缩放和图标数量变化。
- 当悬浮工具条切换到顶部或底部横向布局时，头像必须位于工具条右手边，并与工具条纵向居中对齐；左右两侧纵向工具条仍沿用头像位于工具条下方的跟随规则。
- 工具条位于底部时，常驻快捷栏必须自动移到画布上方，避免和横向工具条、头像占用同一底边；工具条离开底部或抽屉把工具条临时改为纵向时，快捷栏自动回到底部。
- 悬浮工具条提供主题切换按钮：深色主题显示太阳图标并提示切换到浅色，浅色主题显示月亮图标并提示切换到深色；切换后画布、窗口控制、菜单和节点主题同步更新。
- 头像使用白色底图；圆形内部图片按 `100% × 100%` 填满，不固定为旧的小尺寸。
- 设置头像时先打开调整弹窗，缩放范围 100%–250%，确认后输出 256×256 白底 PNG；取消不会覆盖原头像。
- 快捷键说明统一维护在 `app.js` 的 `SHORTCUT_DEFS`，设置 →「快捷键」与 `?` 速查弹窗共用同一份数据，不能再各自维护静态表格。
- 有快捷键的工具图标必须在悬浮提示中显示按键并写入 `aria-keyshortcuts`：资源与历史 `Ctrl+K`、导入 `Ctrl+O`、适应视图 `Shift+F`。
- 画布快捷键与画室对齐：`F` 以选中节点为锚点跟随整理整张连通网络；`Q` 合并选中节点/连通网络为卡片，选中卡片时再按 `Q` 展开；`Shift+F` 适应视图或聚焦选中；按住 `Alt` 拖动复制节点。画布空白处双击不得再触发适应视图。
- 框选采用方向规则：左向右拖框必须完整包含节点或整条连线曲线才选中，右向左拖框与节点或连线曲线相交即可选中；反向框使用更疏的蓝色虚线和更浅填充，并在完成后提示“碰到即选”。框选矩形必须放在独立透明浮层，鼠标移动按 rAF 合并到一帧，只重绘框选层，禁止每次移动都重绘节点和连线主画布。
- 合并卡片保存完整子节点模板与所有相关连线；展开时恢复原节点 ID、节点状态和连线，并在卡片位置附近做防重叠摆放。合并卡片可拖动、双击展开，并参与保存/撤销/恢复。
- 合并卡片尺寸与普通节点统一：宽 320、高 360（`NODE_CARD_H`）；内部预览区随卡片高度自适应。
- 合并/删除节点时必须同时销毁 `gwCameraBadge`（机位序号角标）、星标和旧连线；仅隐藏不够，否则会留下悬浮数字角标。
- `F` 跟随整理已升级为 8 段业务流程分列：结构机位 → 控制参数 → 生成方案 → 生成结果 → 精修/放大 → 图层拆分 → 软装/排版 → 报价/交付。生成节点保持不动，各列按真实尺寸居中并对无关节点做纵向避让。
- 结构机位按 1–4 角标排 2×2/3 列网格；控制参数纵向堆叠；生成结果按生成顺序排 2×2 或 3×3；放大/精修、图层、软装/排版、报价/交付各自独立成列，只有存在节点时才占列。
- 对比、反推提示词、对话是旁路节点，放在结果网格上方展开，不占用主流程列宽。
- 业务流程分列当前只处理选中节点所在的连通网络；跨空间的“房间横向工作带”仍作为下一阶段整理能力。
- 选中两个以上节点后，`↑` 将节点顶边对齐并按 24px 统一横向间距，`←` 将节点左边对齐并按 24px 统一纵向间距；两键分别处理横向/纵向，不掉换轴向，对齐支持撤销。
- `focusNode()` 只接受节点记录（含 `.konva`），不能直接传 Konva 节点；整理/跟随流程用 `focusCanvasNode(konva)` 转换，避免单选或空结果时出现 `undefined.getClientRect` 异步错误。
- 供应商返回 dataURL 后必须先读图验证；无法解码时记录失败并尝试下一个通道，不能把坏数据直接交给 `img:write`。
- 失败占位卡必须保存原始错误 `rawError` 并写入 `gw-boot.log`；同一生成节点开始新生成或重新成功后，自动清除该来源的旧失败卡，避免“生成失败”和“生成中”卡片重叠。
- 失败卡的标题/正文是独立 Konva Group，移动失败卡时必须同步 `gwExtras` 的坐标；代理拖动期间隐藏文字附件，松手后 `syncErrorExtras` 一次归位，不能只移动虚线框。
- 生成结果/失败卡的连线统一使用主流程边样式：`#83A0B2`、无中点圆点、带方向箭头；流光只由 `flowLayer` 绘制，不再在卡片线上保留旧版圆点。
- 文生图节点不能只发送用户提示词。最终 Prompt 必须包含预设风格名、天气、时段/外景/人物/光影、比例、硬装约束和材质基准，否则界面上的风格/天气选择不会生效。
- 点击、框选、拖动节点都不再激活流光；流光只在节点真正生成/运行中显示。`activateNodeFlow` 不再用于选中态。
- 所有连线（包括生成结果卡、失败卡、对比卡）统一从 `visualNodeRect` 计算端点，确保 DOM 参数面板与图片端口对齐；卡片线不再创建中点圆点，统一带方向箭头，流动效果只由 `flowLayer` 绘制。
- 所有节点选中态统一使用纯蓝色外发光，但 Canvas 节点的光晕必须由与节点同尺寸的独立 DOM 层绘制，使用 `#83A0B2`、约 38px 屏幕外发光和 0.78 强度；禁止把光晕阴影直接加在图片节点或卡片本体上。光晕层必须随世界坐标移动、在取消选择时销毁、拖动时隐藏并由拖动副本接替。单选和不超过 4 个节点的多选使用完整光晕；超过 4 个节点时，所有选中节点统一切换为同强度的轻量光晕，不能出现部分节点有光、部分节点没有光。
- Canvas 光晕的 38px 是屏幕视觉基准，必须按 `38 / stage.scaleX()` 换算成世界尺寸，否则画布缩小后光晕会比数据面板弱。缩放结束后 `scheduleViewportSettle` 必须重新调用 `updateSelectionGlowPositions()` 刷新补偿值。
- 代理拖动开始时可临时隐藏光晕，但隐藏对象必须保留在 `hiddenAttachments` 中并在松手后统一恢复；严禁在激活拖动时清空该列表，否则图片节点拖动后光晕会永久消失。
- DOM 参数面板拖动时，必须在 `pointerdown` 后隐藏所有选中的 Konva 光晕底层；面板自身的 CSS 光晕继续跟随面板移动。松手或取消拖动后，按节点新坐标恢复光晕，禁止把蓝色底层留在原位。画布节点代理拖动结束后也必须重新定位光晕。
- 多选后拖动参数节点必须保留整个选区并整体移动全部选中节点，不能把选区压缩成单选；从图片或卡片发起拖动时，生成/参数/材质/光影等 DOM 面板也要按相同位移实时跟随，不能等松手后才跳到新位置。
- 代理拖动结束后的那次 click 必须被抑制，不能因为节点在拖动中被临时隐藏而把选区清空；多选拖动、撤销后都要保留原选区与光晕。
- 可撤销删除使用 `detachNodeEntries` 把节点移出画布时，必须同步隐藏其光晕；`hideNodeAttachments` / `showNodeAttachments` 负责光晕显隐。`updateSelStyles` 还要销毁不属于任何现存节点的孤儿光晕，防止 F 整理、删除、撤销后出现蓝色块。
- 文件拖入时的 `setDropHoverNode` 必须兼容 DOM 参数节点：其 `konva` 是 Group，不存在 `shadowColor()` 等方法。只有 Shape 才调用阴影 API；面板节点改用面板 `drag-candidate` 高亮，必须在离开时移除。
- 机位序号和星标角标在拖动期间必须实时跟随。代理拖动用 `captureBadgeDragStarts` 记录角标起点并按同一位移更新；参数面板拖动在 `rafSync` 中调用 `syncBadgesForNodes`。松手后再统一刷新一次，禁止角标留在原点。
- 多选顺序角标（`selectionBadges`，1/2/3 数字圆圈）是独立图层，不属于机位角标。代理拖动中它们会临时隐藏，松手恢复后必须调用 `positionSelectionBadges()`；参数面板拖动时 `rafSync` 每帧也要刷新顺序角标。`afterMutation()` 统一补一次位置，防止数字角标留在原坐标。
- 拖动节点时连线与连接点不能消失。代理拖动期间，只临时隐藏与拖动节点相关的原连线，并在 `dragLayer` 上用 `gw-drag-edges` 轻量临时层按拖动偏移实时绘制；连接点保留并同步到投影位置。松手后恢复原连线、销毁临时层并刷新端口。参数面板拖动同样走这套拖动连线层。
- 图片节点代理拖动时，选中光晕也不能消失：光晕临时移到 `dragLayer`，用拖动起点的 `baseRects` 加偏移逐帧定位，位于克隆图下方；拖动的临时连线使用同一组 `baseRects`，不能依赖已隐藏节点的实时 `getClientRect`。松手后光晕移回主层并统一恢复位置。
- `edgeBatchDraw` 的 `_visible === false` 过滤只适用于原连线层（`gw-edge-batch`）。临时拖动层（`gw-drag-edges`）绘制的是被原层临时隐藏的相关边，必须忽略该标志，否则临时线也会被跳过而“消失”。
- 文生图/血缘结果线使用旧版 `gwLine`（`createCardLine`），不属于图数据库批量边。拖动时只能隐藏与拖动节点相关的 `gwLine`，并在 `dragLayer` 的 `gw-drag-legacy-lines` 上按同一组基准矩形和偏移重绘；无关血缘线必须保持可见。松手后恢复原线。
- 流光只允许在存在 `gwRunning` 节点时显示。`setNodeRunning(false)` 后若没有其它运行节点，必须调用 `stopEdgeFlowAnimation()` 清理流光层；拖动开始时隐藏流光，松手后只有在确实有运行节点时才恢复，禁止拖动或失败后残留虚线动画。
- 灵动岛“更多”菜单只保留「交换参考顺序」和「网格排版」。方案排版、软装清单、设为空间参考三项移到图片/变体/生成节点的右键菜单，并从节点右侧端口拉出连线时的节点菜单中出现；连线菜单创建排版/软装节点时必须先选中来源节点，确保自动建立连接。

- 底栏固定为三栏网格：左侧只显示缩放、对象数和简短选区摘要，中央保存状态始终位于整个底栏的几何中心，右侧只显示画布视口尺寸。项目名由顶栏承担，版本号与“数据仅存储在本机”移到设置/关于，不再常驻底栏。
- 底栏保存状态只显示“已保存/保存中/失败”和小时:分钟，完整时间与保存模式放在悬停提示；临时 toast、启动日志和 `[history]` 调试信息不得覆盖中央保存状态或写入右侧状态栏。
- 多选时底栏只显示“已选 N 项”加首个对象摘要，单图显示名称、尺寸和 AI 放大档位；所有完整详情保留在悬停提示中，左右两侧使用独立裁剪，禁止挤动中央或互相重叠。
- 底栏中央保存状态不显示灰色底板、线框或胶囊背景，只保留状态圆点和文字；常驻快捷键条的方向键必须使用支持粗体的符号字体并强制加粗。
- 导入与空画布文案不得绑定 SU、微信等单一来源，统一使用“参考图、效果图或材质图”“复制图片后粘贴”等通用表达；默认导入标签使用“参考图 N”。
- 历史版本采用分类保留：自动安全备份与恢复前备份合计保留最近 30 个，手动命名版本保留最近 100 个。恢复前备份不能挤掉客户确认过的手动里程碑。
- 自动安全备份在画布实际保存后检查，最近一次自动版本超过 10 分钟才创建；完全相同的自动快照不重复写入。版本记录必须保存 `kind`（auto/manual/restore）、内容哈希、节点/连线统计和文件字节数。
- 版本历史弹窗必须显示当前版本总占用空间，并结合日期、节点数、连线和单个文件大小展示；版本只保存画布状态与图片引用，不复制 `Content` 原图。
- 空间生成、文生图、彩平图、单张重绘、材质、光影和天气参数必须先整理为结构化语义，再通过统一提示词适配层按具体模型生成最终提示词；不得在各节点中只为某一个模型写死提示词。
- 模型适配层至少区分自然语言、关键词、结构化指令和精简四类表达；新增模型只补模型配置与回归测试，不复制节点逻辑。
- 光影参数提供“自动 / 开启 / 关闭”和“顶面照明 / 灯带灯槽 / 装饰灯”分组。关闭或局部开启仅改变发光状态，不得新增、删除、移动或重塑灯具实体。
- 雨天只通过冷灰天空、柔和漫射光和低反差自然光表现，提示词不得要求生成雨滴、水珠、雨丝、水幕、积水或湿面；需要窗外可见雨景时使用用户外景参考图。
- 有明显功能、UI、提示词或生成效果变化的版本，必须在 `release-evidence/<版本号>/` 保存真实的前后对比图、关键参数、版本日期和测试结果，供验收与后续宣发复用；客户项目和 API Key 必须先脱敏。

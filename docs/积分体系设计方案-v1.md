### 0.1.1 模型选型原则：阿波罗优先，默认用最便宜的可用档

算力全部从阿波罗（apilio）分销，我们是分销商，成本就是它的价目：

1. **新增模型先查阿波罗**。阿波罗有的一律走阿波罗；阿波罗没有才考虑火山直连 / RunningHub，并在 `note` 里写明原因。
2. **同族多档时，默认位只能放最便宜那条**。Seedream 5.0 在阿波罗上有三条：`doubao-seedream-5-0-260128`（¥0.15→1 分）、`seedream-v5-flash`（¥0.80→4 分）、`seedream-v5-pro`（¥0.90→5 分）。三条都接进下拉让客户自选，**默认是 1 分那条**。
3. **高价档必须在 `note` 里写清每张扣几分**。客户点开下拉就该看见差价，不能出完图才发现扣了 5 分。
4. **每条阿波罗生图模型都必须在 `MODEL_COST_YUAN` 登记**，不许靠 ¥0.6 兜底蒙混——兜底价对 ¥0.8 的模型是亏的。

以上 4 条写在 `tests/model-sourcing.test.js` 里：谁把默认改成 Pro、谁加了模型忘了登记成本，测试直接失败。

### 0.2 计价口径：金额是软件费，积分是赠品

**金额 = 软件使用权（按月 / 季 / 年）；积分 = 随订阅赠送的额度。**

- 不存在「58 元买 60 积分」这种对价关系，也不做「元 / 积分」「元 / 张」的换算，更不许反推「这一档划不划算」
- 客户买的是软件能不能用、能不能出图；积分只是让他**不用配自己的 Key 就能立刻出图**
- 内部唯一要看的数字：**客户把赠分全部用光时，这一单还剩多少现金**（价格 − 赠分 × 0.20）。这不是毛利，是赠品兑现成本，用完即止、不用则不发生

### 0.3 内测期 vs 正式期：只差赠分，价格一分不动

内测期至 **2026-11-30**。订阅档在内测期按**双倍**赠分，结束后新购按标准额度；**已到账积分不回收**（绑购买动作，不绑时间段）。
加油包是纯算力包、不含软件授权，**两期面额相同**，也不参与加赠。

| 标准年 | ¥580 / 365 天 | 1200 | 600 | ¥324.00 / ¥162.00 |

## 一、核心模型：一张积分账本，两类用户，自动路由

```
                    ┌─ 无自有 API 用户 ──→ 积分走我们渠道（阿波罗）──→ 用完 → 引导买加油包
用户调用 ──→ 额度路由器 ─┤
                    └─ 有自有 API 用户 ──→ 积分 > 0：走我们渠道（扣积分）
                                          积分 = 0：自动切用户自己的 API（不再产生我们成本）
```

**设计要点：赠送积分是"我们渠道的通用额度"，不是"张数"。**
- 自有 API 用户拿到的积分 = 备用金（他自己 API 挂了/没余额时顶上），权益没白送
- 我们的成本永远只发生在"走我们渠道"的调用上，自有 API 调用零成本
- 没有套利空间：积分只能在我们渠道消耗，作假只能改变"何时切回自有 API"，伤不到我们

## 三、消耗顺序与显示逻辑（修"首付后档位不显示"）

2. 新增"加油包"卡片，**所有档位用户都可见**（包括未订阅用户——先买加油包也是转化入口）
3. 积分余额在两处常显：生成面板角落（小字）+ 订阅页（大字）

## 四、额度路由器（技术实现）

新增 `quota-router.js`，挂在 providers.js 统一出图入口之前：

```
生成请求 → quota-router.resolve(engineId)
   ├─ 查本地积分缓存（云端余额接口，5 分钟 TTL）
   ├─ 积分 > 本次倍率 → 返回"走阿波罗"，同时云端预扣（幂等任务 ID）
   ├─ 积分不足 → 用户配了自有 API？→ 返回"走自有 API" + 面包屑提示"积分已用完，已切换你的 API"
   │              → 没配 → 弹加油包购买引导
   └─ 调用失败/超时 → 回滚预扣（失败不扣分，重试上限 3 次）
```

- **扣分时机**：预扣 + 成功确认 / 失败回滚，任务 ID 幂等，防止刷分
- **自有 API 切换**：纯客户端行为，不经过我们，零成本；切换提示做在生成面板（"本次由你的 API 完成"）
- **云端余额接口**：内测期用现有 ledger + 云函数/OSS 方案即可（42 人规模），转正后再演进
- **对账**：每周 apilio 按 key 用量导出 ↔ 积分消耗记录，误差 >5% 预警（沿用分发模板 SOP）

## 七、消耗透明化（用户怎么知道自己的消耗）

**原则：每次扣分都必须可解释、可回查；余额以云端为准，本地流水只做展示。**

### 三层展示

| 层 | 位置 | 内容 | 时机 |
|---|---|---|---|
| ① 实时反馈 | 生成完成 toast | "本次消耗 2 积分 · 剩余 48"；自有 API 则显示"由你的 API 完成 · 不消耗积分" | 每次调用成功 |
| ② 常驻徽章 | 生成面板角落 | 剩余积分小徽章，2K/4K 调用前 hovering 提示"将消耗 N 积分" | 常显 |
| ③ 明细页 | 订阅与授权 → 积分明细 | 分池余额（订阅积分/加油包）+ 本月合计 + 流水列表 | 随时可查 |

### 流水记录字段（每条）

```
时间 · 渠道（阿波罗/自有API）· 模型 · 规格（1K/2K/4K）· 倍率
· 本次扣分 · 扣分池（订阅/加油包）· 剩余余额 · 任务ID（幂等/对账用）
```

- 失败回滚也记一条（扣分为 0，状态"已回滚"）——用户能看到"失败不扣分"是真的
- 明细页支持按月筛选、导出 CSV（对账党用户安抚）
- 内测期：云端余额接口为权威，本地 userData 流水为展示缓存，每次启动/每次调用后刷新
- 转正后（独立子 key）：余额直接读 apilio dashboard billing API（分发模板第一节的 curl 验证项），流水仍由我们生成

### 明细页 UI 要点

- 顶部两张卡：订阅积分（剩余/本月清零日期）、加油包积分（剩余/有效期）
- 中部一行：本月已消耗 N 积分 · 约 N 张标准图
- 下部流水列表：倒序，最近 50 条，加载更多
- 底部小字："积分消耗按模型与规格倍率计算，倍率表见'关于'"（倍率透明，避免黑箱感）

## 八、充值记账："充了多少"的权威来源

**原则：充值事实锚在钱上，不锚在用户嘴上。云端入账只有两个来源，除此之外没有第三条路能加积分。**

### 入账来源（仅此两个）

1. **兑换码入账**：你签发的带面额积分码（复用 GIWIN2 的 Ed25519 签名体系，码里带 points 字段）→ 用户在 app 输码兑换 → 云端账本 +N。码本身是签名凭证，伪造不了、改不了面额。
2. **支付回调入账**（转正后接自动收款时）：支付平台回调 → 云端账本 +N，订单号可回查。

### 三阶段落地

| 阶段 | 做法 | "充了多少"的依据 |
|---|---|---|
| 现在（人工期，42 人） | 微信收款 → 手填 credit-ledger.csv → 签发码/发 key | 微信账单 ↔ 台账双录；**每周拿微信账单导出对一次，对不上就是漏记** |
| 积分码过渡（0.4.37 起） | 签发积分面额码，用户自助兑换 | 已签发码面额总和 − 已消耗 = 余额，数学自洽；签码时在台账记"码 ID ↔ 微信转账单号"一一对应 |
| 自动支付（转正后） | 接收款通道（虎皮椒/面包多/商家码回调） | 支付回调流水即充值记录，订单号进明细页 |

### 对账闭环（每天 5 分钟 / 每周 30 分钟）

```
微信/支付平台收款合计 = Σ 签发码面额记录（credit-ledger）
云端账本入账合计     = Σ 已兑换码面额
明细页用户看到的余额 = 入账 − 消耗
```

- 用户明细页里"+40 加油包充值（订单 GW…）"那条流水，来源就是上表的入账记录——订单号可追溯到你的收款记录
- 防扯皮：任何余额争议，取云端账本流水 + 你的收款记录对质，两分钟出结论
- 签发台账（ledger.csv）顺手补一列"金额"，把授权账和收款账合到一处看

## 八·五、两种码的分工（1.5.0 起：激活码也带档位）

一个客户可能「只激活不订阅」，也可能「订阅但积分用完了」，所以权限和额度必须能分开补——用两种码，各管一件事：

| | 激活码 `GIWIN2` | 积分码 `GIWIN4` |
|---|---|---|
| 管什么 | 能不能用、用到哪天、**哪个档位** | 有多少积分、积分哪天过期 |
| 关键字段 | `e`（beta / trial / solo / pro）、`x`（到期）、`d`（设备） | `p`（面额）、`pe`（积分有效期）、`x`（兑换截止） |
| 发在哪 | 手机签发器「签发」卡片 | 手机签发器「积分码」卡片 |
| 客户买了什么 | 付订阅费 → 发对应档位的激活码 | 积分包 / 加油包 → 发积分码 |

三条实践规则：

- **只激活的客户**：`e = beta`，用自己的 API Key 出图、不扣积分。顶栏显示「内测成员」，头像上传与粒子魔方不可用
- **订阅客户**：激活码选 `solo`（标准版）或 `pro`（高级版），客户端的顶栏文案、头像上传、粒子魔方、资产库工作流立即按档位解锁；积分再单独发积分码。**激活码里不含积分**，别指望激活一下就送 120 积分
- **续费**：档位不变时只发积分码（不必动激活码）；档位升级或到期，才重发激活码。续期会原样保留档位

为什么档位必须写进签名负载：客户端顶栏、功能闸门全靠 `license.edition` 判定，而它来自验签后的 payload。写在码里 = 改不了；靠「另发一张说明」= 客户重装就丢。

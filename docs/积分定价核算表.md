> 2026-10-30 23:10 实测 `api.apilio.ai/api/pricing`（1126 个模型，`default` 分组倍率 1，`quota_type=1` 表示按次）：

## 一、核心事实：上游按「模型 × 次」定价，不按尺寸

| 模型 | 计费方式 | 实付 | 尺寸是否影响价格 |
|---|---|---|---|
| `seedream-v5-pro` | 按次 | **¥0.90** | 不影响（1K/1.5K/2K 同价） |
| `seedream-v5-pro/layer-decomposition` | 按次 | **¥0.90** | 不影响，**也不按层数**（拆 2 层和 13 层同价） |
| `seedream-v5-flash`（含拆层） | 按次 | ¥0.80 | 不影响 |
| `doubao-seedream-5-0-260128` | 按次 | **¥0.15** | 不影响 |
| `doubao-seedream-4-5-251128` / `4-0` / `3-0` | 按次 | 0.15 / 0.14 / 0.10 | 不影响 |
| `nano-banana-pro` / `nano-banana-2` | 按次 | ¥0.20（4K ¥0.275） | 仅 4K +37.5% |
| `gemini-3-pro-image` | 按次 | ¥0.20（4K ¥0.275） | 仅 4K +37.5% |
| `gemini-3.1-flash-image` | 按次 | ¥0.10（4K ¥0.137） | 仅 4K +37% |
| `gemini-nano-banana-2.1` | 按次 | **¥0.10** | 不影响，**1K / 2K / 4K 同价** |
| `dall-e-3` | 按次 | ¥0.04 | 不影响 |
| `gemini-2.0-flash-exp-image-generation` | 按次 | ¥0.03 | 不影响 |
| `gemini-2.5-flash-image` | 按次 | ¥0.04 | ⚠ 不在 `default` 分组，我们调不通 |
| `gpt-image-2` / `gpt-image-1` | **按 token** | 价目里 `price=0`、`ratio=2.5` | 无法用单价核算 |

**三条结论**：

1. **尺寸几乎不决定成本**。只有 4K 档比 1K 贵 ¥0.075；Seedream 全尺寸同价。
   → 「看多大的图扣多少积分」只能当对外说法，真正的成本变量是**模型**。
2. **同一个 2K，nano 成本 ¥0.20、Seedream 成本 ¥0.90，差 4.5 倍。**
   → 按尺寸统一扣分，必然一边亏一边宰。上一轮做的「2K 一律 2 分」就是这个错。
3. **Seedream 5.0 在阿波罗上有三条通道，差 6 倍**：
   `doubao-seedream-5-0-260128` ¥0.15 → 1 分（**默认**）／`seedream-v5-flash` ¥0.80 → 4 分／`seedream-v5-pro` ¥0.90 → 5 分。
   三条都接到客户端让客户自选，默认放最便宜那条——默认位放 Pro 等于拿最贵的通道当标配卖。
4. **4K 分两条路走，都是 1 积分**（实测 2026-10-31）：
   - 文生图 → `gemini-nano-banana-2.1`（阿波罗 1K/2K/4K 统一 ¥0.10，4K 41 秒）
   - 图生图 → `gemini-3.1-flash-image`（¥0.137，4K 带参考图 29 秒）
   默认的 Seedream 5.0 只到 2K；老的 4K 通道 `nano-banana-pro-4k` 是 ¥0.275（2 分）且 >180 秒超时，
   `gemini-nano-banana-2.1-4k` 带参考图 >300 秒没出图。所以面板的「4K · 换模型」按**有没有参考图**分别推荐，
   不能只按价格挑——便宜那条带参考图会卡死。

## 七、画布侧落地（6 处尺寸选择器统一）

画布里有 6 处尺寸选择器，以前各自 `getSizes` 判断，模型到不了 4K 就干脆不给这个选项，
客户只能自己去模型列表里猜换哪个——猜错就是一次超时加白扣积分。现在统一收口到
`providers.sizeOptions(engineId, model, { withRef })`：

| 位置 | 控件 | 图生图判定 |
|---|---|---|
| 生成控制面板 | `[data-p="size"]` | `structureInputs` / `styleInput` |
| 概念效果图 | `[data-concept-size]` | `structureInput` / `styleInput` |
| 平面表现 | `[data-plan-size]` | `structureInputs` / `styleInput` |
| 节点检查器（详版） | `[data-p="size"]` | `structureInput` / `styleInput` |
| 节点检查器（简版） | `#ni-size` | `structureInput` / `styleInput` |
| 文生图弹窗 | `#tt2i-size` | 无参考图，固定 `withRef:false` |
| 旧生成面板 | `#gp-size` 按钮组 | 独立「4K · 换模型」按钮 |

**两条铁律**：

1. 选到「4K · 换模型」必须**连同模型一起换**（`readSizeChoice` 读出 `switchModel`）。
   只记 4K 不换模型，等于拿跑不通的通道硬撞。
2. 校验「当前尺寸是否合法」要用 `sizeOptionValues`（含 4K 补位项），**不能再用 `getSizes`**。
   否则客户选完 4K，下次重绘就被静默打回 auto，白点一次。

4K 分两条路：**文生图推 `gemini-nano-banana-2.1`（¥0.10，41s），图生图推 `gemini-3.1-flash-image`（¥0.137，29s）**——
实测 NanoBanana 2.1 带参考图跑 4K 等满 300 秒不出图，推错就是一次超时。

生成控制面板此前没有成本行，现已补上（`.gen-cost-line`），口径与旧面板一致：
按模型实付折算，跟随原图时给区间，失败不扣。

回归测试：`tests/canvas-size-ui.test.js`（5 条）+ `tests/model-sourcing.test.js` 的 sizeOptions 分路用例。

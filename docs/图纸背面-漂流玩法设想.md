# 纸背 · 漂流玩法设想

> 暂定名：**纸背**（英文 **Verso**，印刷术语「纸的背面」，正面叫 Recto）
>
> 一句话：让每个用画布的人，压下一句关于设计或心情的话，被另一个陌生人翻到；对方只能按一个你写好的按钮。

状态：设想（未开发、未排期）· 2026-10-30 · 形态已定为「纯文字 + 固定反应」（附录 C）

> 两次收敛：
> ① 原设想的「互回、一次即断」属于平台形态，法律义务重得个人背不动 → 改为**只读漂流**。
> ② 只读形态下投稿者不知道自己被没被看见 → 补上**固定反应**：用户不能打字，只能按按钮。
> 结果是：能到达别人眼前的文字只剩两种——你审过的投稿，和你写的词库。

---

## 1. 为什么做

设计工具用久了会变成一台机器：开机、出图、导出、关机。让人愿意每天打开它的往往不是功能，而是「今天会不会有点意外」。

这个玩法的价值不在「能跟陌生人聊天」，而在**我写下的东西，真的被另一个人看见了**。它成本极低、留存很实，且用户会主动去讲。

关键是：**看得到回应，但找不到人**。一句「抱一下」就够，不需要后续。

对外不叫「漂流瓶」，叫**图纸背面**——建筑师本来就会在图纸背面画草图、写牢骚，谁翻到谁看见。这个概念不需要解释。

## 2. 核心规则

| 环节 | 规则 |
|---|---|
| 投稿 | **纯文字，≤40 字**。不接受图片，不接受联系方式（手机号/微信号/QQ/链接一律不上架） |
| 频率 | 每人每 24 小时可投 1 条、可翻 3 次 |
| 审阅 | 投稿先进私有收件区，**人工过审后才进公开池**，同时标一个情绪标签。不经审阅，不会出现在任何人眼前 |
| 翻阅 | 用户主动点图标翻，客户端从公开池**本地随机**抽一条。**绝不主动弹窗** |
| 反应 | 只能从 4 个预设按钮里选一个，**没有输入框**。词库由你写，详见第 5 节 |
| 匿名 | 展示时只给随机三字代号（青砖 / 南窗 / 灰檐），不显示账号、地区、任何联系方式 |
| 退场 | 公开池按批更新，旧批保留 30 天后下线，不堆积 |
| 不对话 | **不能打字给任何人**。这一条是法律分界线，不是产品偏好 |

三条设计红线：

1. **不做实时「发送—等待」**。投出去就当石沉大海，被翻到才是惊喜。回执也是延迟聚合的。
2. **不做关系**。没有好友、没有历史、没有搜索、没有「再找他」。一旦有「关系」，它就是社交产品，成本和风险完全不同量级。
3. **不做自由输入**。投稿只有 40 字，反应只有按钮。能传递的信息量被物理限死，这是整套方案安全的地基。

> 投稿会不会被采用不告知、不承诺、不催办。投稿页只写「压上了」，不写「等待回应」。

## 3. 界面位置与节奏

- 入口：画布右下角一个很小的图标（不占工具栏），点击展开「翻一张」按钮
- 投稿入口在同一个面板里，不单独占位
- 投稿浮层：单行输入框 + 字数计数（x/40）+ 「压上」。没有图片、没有附件、没有富文本
- 翻到一条时，以浮层出现：**一张纸条**（等宽字、细边框、带一点手写感）+ 代号 + 4 个反应按钮
- 纸条下方一行小字固定提示：**这儿不能回话**
- 池子空时文案不能写「暂无数据」，要写人话：「这会儿桌上没压着东西，晚点再来翻」

**排版是生死线**。纯文字很容易显得单薄，一定当**贴上去的纸条**做：纸面略偏暖、边框 0.5px、行距松、字偏小。不要做成卡片，更不要做成聊天气泡——一旦像聊天，用户就会期待能回。

入口不弹窗、不角标、不计数。它是「休息一下」的动作，不是打扰。

## 4. 最小技术形态（无服务器进程）

第一版**不需要服务器、不需要数据库、不需要接口**。只用到三样已经有的东西：OSS、静态文件、客户端本地逻辑。

| 动作 | 怎么做 |
|---|---|
| 投稿 | 客户端用**预签名表单**把一个很小的文本文件直传 OSS 私有前缀 `inbox/`。只能写、不可读不可列、**4KB 上限**、7 天自动删除 |
| 审阅 | 人工作业：从 `inbox/` 拉下来读，通过则写入公开静态池 `bottles.json`，并标一个情绪标签 |
| 翻阅 | 客户端 GET 静态 JSON，**在本机随机抽一条**。不请求接口、不记录行为、不上报 |
| 反应 | 客户端把选中的按钮写成一个短字符串，同样落到 `inbox/`。不实时推送 |
| 退场 | 按批次下线，改 JSON 即可，无需清理任务 |

**明确不需要**：常驻服务、数据库、账号体系、会话中继、消息队列、实名系统、图片存储。

> 4KB 上限不是随手定的：40 个汉字加时间戳不到 1KB。物理上就不可能塞进一张图、一段语音或一个附件。约束由存储层直接执行，不依赖客户端自律。

为什么能这么轻：这里**没有“给另一个人”的动作**。投稿只是进你的收件箱，被人看到必须经过你上架这一步。整个链路是「用户 → 你 → 所有人」，不是「用户 → 用户」。少了那一段，整套实时基础设施连同它的法定义务一起消失。

## 5. 反应机制（固定词库）

只读形态最大的病是：投稿者永远不知道自己有没有被看见，投一次就不投了。
反应不是社交，是**回执**——它只证明一件事：有人翻到了。

### 5.1 硬规则

1. **不给键盘，也不给 emoji 面板**。只给 4 个按钮。自由 emoji 也能传信息（`🍆` `📍` `数字` 组合就是暗语），还不好用关键词过滤。
2. **词库不带任何可联系信息**：无数字、无地名、无时间、无账号、无「加我」类引导。
3. **一条最多收 5 个反应**，满了关闭。不给反应者看历史，不显示谁按的、按了几次。
4. **不实时推送**。回执在下次打开时聚合显示：「你压的那张，有 3 个人翻到了，2 个人留了话」。

### 5.2 词库（按情绪分组）

单一套通用词库对不上任意内容——人家写「被甲方改了七版」，你只给「说得对」，那是侮辱。
所以**审阅时顺手标一个 tone**，存进静态 JSON，客户端据此显示对应那组。不需要 AI，不需要接口。

| tone | 适用内容 | 四个按钮 |
|---|---|---|
| **吐槽 / 累了** | 改图、加班、甲方、通宵 | 抱一下 · 我也一样 · 撑住 · 别改了，睡吧 |
| **成了 / 得意** | 中标、过审、终于对了 | 好看 · 稳 · 可以啊 · 记下了 |
| **观点 / 想法** | 对设计的看法、经验、判断 | 说得对 · 我也这么想 · 这句我收了 · 有道理 |
| **低落 / 丧** | 迷茫、想转行、被否 | 会过去的 · 我懂 · 别硬撑 · 明天再说 |
| **兜底** | 归不进去的中性内容 | 看过了 · 有点意思 · 慢慢来 · 记住了 |

分组要宽不要细，四组加兜底是上限。分组一多，你标注的负担上升，就会开始偷懒全标兜底，分组白做。

> 降级方案：懒的时候全标「兜底」也能跑，能跑但体验打折。不阻塞开发。

### 5.3 为什么这样仍然安全

词还是你写的。用户能做的仍然只是「按第 3 个按钮」，只是这个按的动作和内容对上了。
法律定性一点没变，甚至更稳：连「显示哪些按钮」都由你决定。

## 6. 合规清单（纯文字形态下剩这些）

因为不构成信息发布／即时通讯服务，也不向其他用户自动分发可编辑内容，**实名、日志留存、经营许可、安全评估这四项不适用**（理由见附录 C）。

剩下必须做的四样，都很轻：

| 必做 | 怎么做 |
|---|---|
| 投稿授权 | 投稿页勾选一句话才允许提交（原文见 C.4） |
| 审阅即入口 | 不经过你手就上不了架。审核在物理上无法绕过，不靠自觉 |
| 内容三卡 | 卡联系方式、卡辱骂地域、卡政治敏感。纯文字下这三项就是全部内容风险 |
| 下架通道 | 收到异议立即从 JSON 里删。不需要后台，改文件即可 |

> 补充：不设“举报按钮”也能合规，因为你可以被邮件/微信找到；但公开渠道（官网/商店）必须挂一个可联系的邮箱。

## 7. 分阶段范围

**第一版（内测 10 人）只做：** 纯文字投稿（≤40 字 + 授权勾选）、人工审阅与标 tone、静态池、本地随机翻阅、4 按钮反应、延迟聚合回执。

**明确不做：** 自由输入、对话、好友、历史记录、搜索、重逢机制、任何形式的「找人」、公开墙、图片投稿。

**第二版再看：** 机审辅助、投稿量上来后的自动收件整理。**图片投稿不建议做**，那是唯一会引出民事索赔的入口。

## 8. 怎么判断它成了

| 指标 | 目标 | 说明 |
|---|---|---|
| 投稿 → 上架率 | > 70% | 低于 50% 要么门槛太高，要么内容不达预期 |
| 翻阅 → 看完率（停留 >5s） | > 60% | 翻了就走，说明内容不吸引 |
| 翻阅 → 按一个反应 | > 50% | 低于 30% 说明词库对不上内容，要改词而不是加功能 |
| 一周内二次投稿率 | > 30% | 这是留存信号，比日活更可信 |
| 10 人里一周翻 ≥3 次的人数 | ≥ 4 人 | 少于 2 人说明它只是尝鲜 |

> 「反应率」是这个玩法唯一真正要紧的指标。因为它是「被看见」的直接证据：投稿者拿到回执，才会投第二次。

## 9. 已知代价

- **词库总会有对不上的时候**：分组能解决大部分，但一定有人写一句你四组都套不上的话。宁可用兜底，不要为了「对得上」放开自由回复。
- **不能回话，用户会不满足**：这是形态的硬边界，不是 bug。入口和纸条下方都要写清楚。
- **审阅由你一人完成，延迟不可控**：忙的时候可能两天不上架。投稿页绝不承诺时间。
- **投稿可能不被采用**：比“被采用但没人反应”更难接受。文案要把「石沉大海」前置说清楚，不要事后道歉。
- **纯文字容易显得单薄**：没有图掍场面，排版不好就会像弹幕。纸条质感是这个功能的生死线。
- **小基数体验差**：10 人阶段公开池可能只有十几条，反复翻会看到重复。定期换批是唯一解法。

---

## 10. 需要拍板的三件事

1. **词库定稿**：第 5.2 节那 20 个词是我按行业语感起的草稿，你可以直接改词（改完同步到 JSON）
2. **换批节奏**：一周一批（每批 15–25 条）还是一月一批？快一点新鲜感强，但你的审阅负担更重
3. **代号要不要常驻**：每批换一个代号（更像陌生人）还是固定一个（像栏目作者）？我偏向前者

# 附录 A · 名字与语言

## A.1 候选与取舍

名字不只是好听，它决定会招来什么样的内容。

| 名字 | 意象 | 会招来什么 | 风险 |
|---|---|---|---|
| **纸背** ✅ | 纸的另一面，「力透纸背」 | 私密、带点分量的话 | 略文艺，门槛稍高 |
| 透光 | 把纸对着光，背面痕迹透出来 | 温柔、克制 | 太通用，商标难注册 |
| 叠图 | 两张图叠着对位，只重合一次 | 短暂相遇感最强 | 动词化后偏技术味 |
| 废稿 | 画废的稿子，谁也不评判谁 | 自嘲、轻松，参与率最高 | 作品感弱，易变吐槽墙 |
| 图背 | 图纸背面 | 中性直白 | 少了点味道 |
| 红线 | 审图时红笔批注 | 有行业黑话感 | 语感偏严肃，易联想到「底线」 |

**选定：纸背 / Verso。**

- 「背面」把设定说全了又没说破：匿名、藏起来、不示人
- 「力透纸背」是现成的品牌故事——一句话写得有劲，能穿透纸面被另一面的人感受到，与玩法严丝合缝
- 英文 **Verso** 是印刷术语的「纸背」（正面为 Recto），建筑与出版行业一看就懂，不出海也能当副标用

**备选策略**：若一个月后投稿率上不去，往「废稿」方向放松入口文案（如「压一张废稿」），名字不必换。

## A.2 动作也用同一套语言

| 通用说法 | 这里的说法 |
|---|---|
| 投稿 | 压一张 |
| 提交成功 | 「压上了」（不承诺结果） |
| 翻阅 / 抽一条 | 翻一张 |
| 翻看下一张 | 再翻一张 |
| 收起来 / 结束 | 收起来 |
| 想回复但不能 | 「这儿不能回话，想说就自己压一张」 |
| 空池子 | 「这会儿桌上没压着东西，晚点再来翻」 |

全套动词沿用行业语义，一句解释都不需要。避免直接用「发送、接收、聊天、结束」，那会立刻出戏。

> 原方案里的「对个光」（开始对话）、「散了」（对话结束）已随对话形态一起去掉。留在这里只是说明取舍：**动词表里没有“对话”这一格，是故意的**。

# 附录 B · 法律风险评估

> 以下为产品侧梳理，**不构成法律意见**。真要上线，请律师或合规顾问按实际主体、服务器所在地再核一遍。

## B.0 结论先行

这个功能不是「加个玩法」，而是让产品从**本地软件**变成**网络服务提供者**。一旦有用户之间的信息传递，平台责任（内容、实名、留存、许可）会整套上身，且不随用户量小而变化。10 个用户和 1 万个用户，义务是一样的。

## B.1 三类会直接改技术方案的硬约束

**① 后台实名**
《网络安全法》第 24 条：为用户提供信息发布、即时通讯等服务，应当要求用户提供真实身份信息；不提供的不得提供服务。
→ 「双方互相匿名」没问题（前台自愿），但**平台侧必须能关联到真实身份**。目前产品只有授权码，没有实名体系，这是一块新增成本。

**② 日志留存 6 个月**
《网络安全法》第 21 条：按规定留存相关网络日志不少于六个月。
→ 与设想里「会话只在内存、断开即删、不写正文」**直接冲突**。至少要留存：谁、何时、投递/捞取了哪条、IP 与设备信息。正文是否留存，取决于配合调查的能力要求。
→ 这还牵出一个诚信问题：如果对外承诺「关掉就再也找不到」，而平台后台其实留了记录，文案与事实不符；反过来若真的什么都不留，出事时无法配合取证，责任更重。**这条必须在上线前想清楚怎么写用户协议。**

**③ 经营许可与安全评估**
- 《互联网信息服务管理办法》：经营性服务需增值电信业务经营许可，非经营性需备案
- 《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》：上线前需自评估并在平台提交报告
→ 陌生人内容传播很可能被认定为「具有舆论属性或社会动员能力」，安全评估大概率要做。

## B.2 风险分级

> 本节按**原设想（含图、可互回）**列出，用于说明为什么要降级。
> 本篇已定为「纯文字 + 固定反应」：其中「图纸泄露」已基本灭绝，「未成年人接触」「诈骗引流」也随自由对话的取消大幅下降。
> 现行方案的实际风险清单以 **C.5** 为准。

| 等级 | 风险 | 说明 |
|---|---|---|
| 🔴 高 | **未成年人接触** | 《未成年人网络保护条例》要求未成年人模式；没有实名就无法识别，一旦出事平台责任极重 |
| 🔴 高 | **客户图纸/涉密工程泄露** | 设计行业特有。投的「废稿」常含甲方项目、地块、甚至涉密工程信息，泄露后果远超普通 UGC |
| 🔴 高 | **诈骗与引流** | 匿名一次性通讯是诈骗温床，平台需反诈提示与处置能力 |
| 🟡 中 | 内容违规（九不准） | 需审核与处置机制 |
| 🟡 中 | 著作权侵权 | 投他人作品/甲方图纸，需「通知—删除」通道与用户承诺 |
| 🟡 中 | 个人信息处理 | 代号、IP、图片的收集需告知同意、最小必要（PIPL） |
| 🟢 低 | 双方口角、言语冲突 | 有举报与拉黑即可 |

## B.3 三条降风险路线（按代价从低到高）

| 路线 | 形态 | 是否构成即时通讯 | 主要代价 |
|---|---|---|---|
| **A. 只读漂流** | 只能看别人写的字，**不能回话**（可配固定反应按钮） | 否 | 无需实名，只需内容审核。风险最低 |
| **B. 异步留言** | 可回，但延迟、有审核、可举报删除，不承诺私密 | 边界模糊 | 需审核与留存，可能被要求实名 |
| **C. 完整双向会话**（原设想） | 实时对话、一次即断 | 是 | 实名 + 留存 + 安全评估 + 用户协议重写，全套餐 |

**建议**：先做 **A**。它已经能验证这个玩法的核心假设——「我投出去的东西被另一个人看见了」这件事是否真的成立。数据好再谈 C，那时才值得为它承担整套合规成本。

> 落地形态、技术实现与个人主体的可行性，见**附录 C**。**本篇已按 A 定稿，B 与 C 仅作对照保留。**

# 附录 C · 个人主体的最小合规形态（本篇定稿方案）

> 同上，产品侧梳理，**不构成法律意见**。真要上线，请按实际主体与服务器所在地核一遍。

## C.0 一句话

**不做平台，做编辑。** 平台让用户的内容自动流向另一个用户，编辑是把内容挑出来、审一遍、由自己发布。前者义务是整套的，后者只对内容本身负责。个人创作者只有后者走得通。

## C.1 判断标准不是「有没有服务器」

而是这一条：**用户投的东西，会不会不经过你就出现在另一个用户眼前。**

- 会 → 你是信息发布/即时通讯服务的提供者，实名、留存、许可、安全评估整套上身
- 不会 → 你是内容发布者，义务变成「内容合规 + 有授权 + 能下架」

所以技术方案再轻、服务器再少，只要存在「用户 → 用户」的自动通道，定性就是平台。反过来，只要每一条内容都必须过你手，定性就是编辑——哪怕用了 OSS、用了接口。

这也是为什么原设想的「互回、一次即断」必须去掉：它恰好就是那条自动通道。

## C.2 形态：投稿 → 审阅 → 随机翻阅

```
用户A 投稿 ──→ [ 私有收件区 inbox/ ] ──→ 你审阅 ──→ [ 公开静态池 ] ──→ 任何用户本地随机翻到
                    （不可读）                              （已审）              （只读）
```

三个特征缺一不可：

1. **投稿不即时可见**，且不通知结果
2. **上架必须经你**，没有自动路径
3. **翻阅是只读 + 本地随机**，不回传任何行为数据

## C.3 技术实现（无服务器进程）

投稿要「写」，翻阅要「读」，两者分开处理：

**写：OSS 预签名表单直传（纯文本）**

- 客户端把 40 字文案写成一个小 txt，直接 POST 到 `inbox/` 前缀，不经过任何服务
- 策略锁死：**只允许写这一个前缀**、单文件 ≤4KB、仅文本类型
- `inbox/` **不可读、不可列举**，客户端拿不到别人的投稿，外部也爬不到
- 生命周期规则 **7 天自动删除**，被灌垃圾也会自清
- 签名预生成嵌在客户端，**不含 AccessKey**；泄露的最大后果是往那个不可读、会自删的目录里倒垃圾
- **4KB 上限本身就是安全阀**：40 汉字加时间戳不到 1KB，物理上塞不进图、语音、附件

**读：静态 JSON + 本地随机**

- `bottles.json` 里是一批已审条目：`{ text, code, tone }`
- `tone` 由你在上架时标，客户端据此选哪一组反应按钮
- 客户端 GET 后在本机 `Math.random()` 抽一条
- 不请求接口、不上报、不记录谁翻了什么

**反馈：同样落进 `inbox/`**

- 用户按下的按钮写成一个短字符串（瓶 ID + 按钮编号），不实时推送
- 你拉取时聚合，下一版客户端才能看到回执

**退场**：改 JSON 即可，无清理任务。

**成本**：内测期一个月几分钱（存储 + 少量流量），没有固定月费。

## C.4 投稿授权原话（照抄即可）

投稿页勾选框，不勾不能提交：

> 这段文字由我本人原创，不含他人项目信息与隐私；同意极物在「纸背」栏目中匿名展示这段文字，我可随时要求下架。

这一句话同时解决三件事：著作权授权、隐私免责、下架通道。**保留勾选记录**（投稿时间 + 勾选状态即可），这是日后唯一的免责证据。

> 纯文字版比带图版的好处：不需要再声明「不含甲方项目名称、地块位置」，因为根本没有图可传。授权语短一半，用户更愿意勾。

## C.5 风险与对策

| 风险 | 为什么对个人致命 | 对策 |
|---|---|---|
| ~~涉密/甲方图纸外泄~~ | **纯文字后几乎灭绝**。不再传图，就没有图纸可泄。这也是选纯文字的首要理由 | 保持「不接受图片」即可，不需额外动作 |
| **著作权侵权** | 抄了别人的句子 | 授权勾选 + 收到异议立刻下架 + 保留投稿记录 |
| **联系方式渗透** | 40 字里塞微信号太容易 | 审阅时卡死：手机号、微信号、QQ、链接、二维码描述一律不上架 |
| **辱骂 / 地域 / 政治敏感** | 心情类内容比图纸更容易踩线 | 宁可不上架。你只有 10 个用户，丢一条不影响，留一条可能出事 |
| **词库被反过来利用** | 若以后放开自定义，风险回升 | **锁死不可自定义**。改词只能你改，不能用户提 |
| **未成年人** | 责任最重 | 无陌生人会话、无自由对话，此风险基本解除；不做任何线下引导 |
| **恶意灌垃圾** | 占存储、污染收件区 | 4KB 上限 + 7 天自删 + 只能写不可读；量异常就换签名或在清单里关掉投稿开关 |
| **监管问询** | 个人没有法务 | 内容全在你手里、可即时下架、规模小。这是「编辑」比「平台」最实在的好处 |

## C.6 什么时候才考虑升级

别提前花钱。三个信号同时出现再谈：

1. 投稿量大到你一周审不完（说明有人在认真用它）
2. 有人明确问「为什么不能打字回」
3. 你愿意为此注册主体、接受实名与留存义务

**只出现第 2 条不足以升级**——想做社交是产品冲动，做合规是法律成本，两者不能混着决策。

> 反应按钮已经能接住大部分「想回应」的冲动。真正接不住的，是「我想认识这个人」——那个需求一旦出现，就不是靠加功能解决，而是另一个产品。

## C.7 一次性配置的坑（真正动手时看）

- 桶策略**只对 `inbox/` 前缀开匿名写**，配错会把整个桶变成可写，这是唯一的高危操作
- 先在测试桶验证策略只对该前缀生效，再动正式桶
- 签名有效期给长（一年），跟版本走，换版本时一并轮换
- 客户端内置一个「投稿开关」，从静态配置读；出事时改配置即可全局停用，不必发版
- **词库也要能从静态配置读**，不要硬编在 asar 里——改词不应要求发版
